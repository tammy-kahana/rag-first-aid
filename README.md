# 🩹 עזרה ראשונה ובטיחות בבית – מערכת RAG

מערכת שאלות ותשובות בעברית בנושא עזרה ראשונה ובטיחות בבית.
המשתמשת שואלת שאלה בשפה טבעית, המערכת מאתרת את הקטעים הרלוונטיים במאגר המסמכים, ומודל שפה מנסח תשובה **על סמך הקטעים האלה בלבד**. לצד כל תשובה מוצגים המקורות שעליהם היא מבוססת.

> המידע במאגר כללי ואינו מחליף הדרכה מוסמכת או גורם רפואי. במצב חירום: מד"א 101.

---

## הוראות הרצה (Windows)

**דרישות מוקדמות:** Python 3.10 ומעלה, ומפתח API חינמי של Google Gemini מהאתר [aistudio.google.com](https://aistudio.google.com).

```powershell
# 1. יצירת סביבה וירטואלית והפעלתה
py -m venv .venv
.venv\Scripts\activate

# 2. התקנת הספריות
python -m pip install -r requirements.txt

# 3. יצירת קובץ .env בתיקייה הראשית עם השורה:
#    GOOGLE_API_KEY=המפתח_שלך

# 4. בדיקה שהמפתח והמודלים זמינים
python check_key.py

# 5. הרצת הממשק
streamlit run app.py
```

**הרצת הבדיקות:**
```powershell
python run_tests.py                   # כל שאלות הבדיקה, נשמר ב-results.md
python run_tests.py --retrieval-only  # שלב האחזור בלבד (ציוני דמיון, בלי מודל שפה)
```

בהרצה הראשונה המערכת בונה את האינדקס ושומרת אותו בתיקייה `chroma_db`. בהרצות הבאות היא טוענת אותו משם ולא יוצרת את ה-Embeddings מחדש.

## ארכיטקטורת המערכת

```
              ┌──────────────── שלב ההכנה (פעם אחת) ────────────────┐
  data/*.txt ─► SimpleDirectoryReader ─► SentenceSplitter ─► Gemini Embedding ─► ChromaDB
              └──────────────────────────────────────────────────────┘

              ┌──────────────────── שלב השאלה ─────────────────────┐
  שאלה ─► Embedding לשאלה ─► אחזור top_k=3 מ-ChromaDB (cosine) ─► סינון לפי ציון דמיון
                                                              │
                     ┌────────────────────────────────────────┼──────────────────────┐
                     ▼                                        ▼                      ▼
       הציון הגבוה < 0.67                     אין מקטע מעל 0.73        יש מקטעים מעל 0.73
       "אני מורשה לענות רק על..."           "המידע לא נמצא במאגר"    Gemini LLM ◄─ Prompt
       (בלי קריאה למודל)                     (בלי קריאה למודל)         ▼
                                                                    תשובה + מקורות
```

| קובץ | תפקיד |
|---|---|
| `rag_engine.py` | הליבה: טעינה, חלוקה, Embeddings, אחזור, סינון ויצירת תשובה |
| `app.py` | ממשק צ'אט ב-Streamlit: בחירת אסטרטגיית Chunking ו-top_k, מספר המקטעים במאגר, כפתור "נקה שיחה" וטיפול מסודר בשגיאות |
| `run_tests.py` | הרצת שאלות הבדיקה ושמירת התוצאות |
| `check_key.py` | בדיקה שהמפתח עובד ושהמודלים זמינים במסלול החינמי |
| `data/` | 8 קבצי טקסט: מצבי חירום, כוויות, דימומים, חנק, החייאה, הרעלות, שברים, בטיחות בבית |

## בחירות טכנולוגיות

| רכיב | בחירה | נימוק |
|---|---|---|
| שפה וספרייה | Python + LlamaIndex | לפי דרישות המטלה |
| מודל שפה | `gemini-3.5-flash` | חינמי, טוב מאוד בעברית ומהיר. `temperature=0` לתשובות עקביות, שמתאימות לתחום רפואי |
| מודל Embeddings | `gemini-embedding-2` | חינמי, תומך בעברית. אותו ספק ואותו מפתח כמו מודל השפה |
| Vector Store | ChromaDB (מקומי), מדד `cosine` | נשמר כקבצים על המחשב, בלי שרת או הרשמה. cosine הוא המדד המקובל לדמיון בין Embeddings (ברירת המחדל של Chroma היא L2) |
| חלוקה למקטעים | `SentenceSplitter` | מחלק לפי משפטים, כך שמשפט לא נחתך באמצע |
| ממשק | Streamlit | צ'אט בדפדפן במעט קוד, עם תמיכה בכיוון ימין-לשמאל |
| מפתח API | קובץ `.env` + `python-dotenv` | המפתח לא מופיע בקוד, ו-`.gitignore` מונע את העלאתו ל-GitHub |

**Prompt:** המודל מונחה לענות בעברית ורק על סמך הקטעים שאוחזרו, לסרב לשאלות שלא בנושא, להחזיר משפט קבוע כשאין מידע, ולהזכיר את מד"א 101 בכל מצב חירום. בנוסף הוא מונחה להתייחס לתוכן המסמכים כאל מידע בלבד, ולא כהוראות, כהגנה מפני Prompt Injection.

## בעיות שנתקלתי בהן ואיך פתרתי

### 1. שגיאת SSL: החיבור ל-Google נחסם
**הבעיה:** כבר בבדיקה הראשונה התקבלה השגיאה `CERTIFICATE_VERIFY_FAILED`. המחשב מחובר לסינון אינטרנט (נטפרי), שבודק תעבורה מוצפנת בעזרת תעודת אבטחה משלו. Windows והדפדפן מכירים את התעודה הזו, אבל Python משתמש ברשימת תעודות פרטית שבה היא לא מופיעה.
**הפתרון:** הספרייה `truststore` גורמת ל-Python לסמוך על מאגר התעודות של Windows. שתי השורות `import truststore` ו-`truststore.inject_into_ssl()` בראש הקוד פתרו את הבעיה, בלי לבטל את בדיקת האבטחה.

### 2. מקטעים קטנים מדי נתנו תשובה חלקית (השוואת Chunking – בונוס)
**הבעיה:** השוויתי שתי אסטרטגיות חלוקה: `small` (256 טוקנים, חפיפה של 30) ו-`large` (1024 טוקנים, חפיפה של 100). בשאלה "הילד שלי שתה חומר ניקוי", אסטרטגיית `small` החזירה רק שלושה צעדים ראשונים. התוצאה חזרה על עצמה בשתי הרצות נפרדות. המקטעים הקטנים חתכו את הקטע באמצע, והחלק "מה לא עושים" (לא לגרום להקאה) והמספר של מרכז ההרעלות לא הגיעו למודל.
**הפתרון:** עם `large` התשובה הייתה מלאה, כי כל נושא נשאר שלם בתוך מקטע אחד. המסקנה: כשהמסמכים קצרים ובנויים כרשימות של הוראות, מקטע גדול שומר על ההקשר. מקטעים קטנים מתאימים יותר למסמכים ארוכים עם עובדות נפרדות. שתי האסטרטגיות זמינות לבחירה בממשק.

| | small | large |
|---|---|---|
| מספר מקטעים | 75 | 16 |
| שאלת חומר הניקוי | 3 צעדים בלבד | תשובה מלאה, כולל "מה לא עושים" ומספר מרכז ההרעלות |
| שאלות קצרות (קצב החייאה, דימום מהאף) | תשובה נכונה | תשובה נכונה |

### 3. מקטעים לא רלוונטיים נשלחו למודל והוצגו כ"מקורות"
**הבעיה:** שלב האחזור תמיד מחזיר את 3 המקטעים **הקרובים ביותר**, גם כשאף אחד מהם לא קשור. בשאלה על עקיצת דבורה נשלחו למודל קטעים על כוויות ודימום. המודל ענה נכון שאין מידע, אבל: (א) **בזבוז טוקנים**, כי נשלחו למודל קטעים מיותרים; (ב) המקטעים הוצגו למשתמשת כ"מקורות" לתשובה שאין לה מקור, וזה מטעה. במערכת עם מסמכים פנימיים, זה גם עלול לחשוף מידע שלא נשאל.

**הפתרון, בשלושה צעדים:**
1. **מעבר למדד cosine ב-Chroma**, במקום ברירת המחדל L2, כדי שהציון ישקף דמיון במשמעות בצורה המקובלת. הסדר בין המקטעים לא השתנה, רק סולם הציונים.
2. **ניסוי לקביעת ספים:** הרצתי את שאלות הבדיקה במצב `--retrieval-only` ובדקתי את הציונים:

| סוג שאלה | ציון המקטע הקרוב ביותר |
|---|---|
| שאלות רלוונטיות (1–5) | 0.745 עד 0.797 |
| בנושא, אבל אין מידע (עקיצת דבורה) | 0.711 עד 0.718 |
| לא בנושא בכלל (איזה יום היום) | 0.636 עד 0.654 |

3. **שני ספים בקוד**, בין הקבוצות:
   - `SIMILARITY_CUTOFF = 0.73`: מקטע מתחת לסף לא נשלח למודל ולא מוצג כמקור. אם לא נשאר אף מקטע, המערכת עונה "המידע הזה לא נמצא במאגר שלי" **בלי לפנות למודל**.
   - `OFF_TOPIC_CUTOFF = 0.67`: אם גם המקטע הקרוב ביותר מתחת לסף, המערכת עונה שהיא מורשית לענות רק על עזרה ראשונה ובטיחות בבית.

**התוצאה:** בשאלות ללא תשובה זמן התגובה ירד מכ-7 שניות לכ-1 שנייה, ולא נצרכה בקשה ממכסת מודל השפה. גם בשאלות רלוונטיות סוננו מקטעים חלשים. למשל, בשאלת הכוויה (`large`) כבר לא נשלח הקטע מ-`07_falls_fractures.txt`.

### 4. מכסה יומית של המסלול החינמי (שגיאה 429)
**הבעיה:** אחרי כמה הרצות התקבלה השגיאה `429 RESOURCE_EXHAUSTED`: המסלול החינמי מוגבל ל-20 בקשות ביום לכל מודל. כל הרצה של הבדיקות על שתי האסטרטגיות צרכה 12 בקשות, וההרצה נעצרה באמצע. כל התוצאות שכבר התקבלו אבדו, כי הן נשמרו רק בסוף.
**הפתרון:** (א) כל תשובה נשמרת לקובץ מיד אחרי שהיא מתקבלת; (ב) בשגיאת מכסה הקוד עוצר עם הודעה ברורה בעברית, ולא מנסה שוב לשווא (ניסיון חוזר נשאר רק לשגיאת עומס זמנית, 503); (ג) הספים מבעיה 3 חוסכים קריאות למודל בשאלות שאין להן תשובה; (ד) מצב `--retrieval-only` בודק את שלב האחזור בלבד, בלי לצרוך את מכסת מודל השפה. בדרך התגלה שגם **יצירת** אובייקט מודל השפה פונה ל-Google ונספרת במכסה, ולכן המודל נוצר רק ברגע שצריך לנסח תשובה.

## הערות ומגבלות
- **ספי הדמיון נקבעו לפי מספר קטן של שאלות.** במאגר גדול יותר צריך לכוונן אותם מחדש על סט שאלות רחב יותר.
- **הרשאות:** במאגר הזה כל המידע ציבורי. במערכת עם מסמכים רגישים יש לאכוף הרשאות **לפני** שלב האחזור, ולא להסתמך על הנחיות למודל.
- **מגבלות המסלול החינמי:** מספר הבקשות לדקה וליום מוגבל, וזמינות המודלים משתנה. `check_key.py` בודק אילו מודלים זמינים בפועל.
